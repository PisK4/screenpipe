## Question

生成任务嵌进 fork 的哪个现成机制？候选都在仓库里现成：pipes 的 ScheduleConfig 周期调度、src-tauri 侧 tokio 循环 + ROUTE-DIRECT-CHAT 单次模型调用（见 `doc/FEATURE_MODEL_INVOCATION_INVENTORY.md`）、起一个 Pi 子进程会话。判据是「最大复用 fork 现成件、最少新建基础设施」，不是满足 Cue 合同的会话形态；合同里的工具白名单、中止边界只在选定形态后当作参照检查一遍。重写一张卡 = 再跑一轮同样的生成，是否需要独立机制也在此确认。

## Resolution

Status: Resolved
Claimed by: pis（2026-08-22，与用户逐项裁决）

### 决议：候选 B——Rust 侧心跳 + 单次直调，两层结构

1. **排除 pipes**：pipes 是第三方扩展面（用户可装卸的插件），核心产品功能不挂在它的生命周期上。
2. **选定 B**：Rust 侧定时器到点后，查增量信号 → 内部调 `/activity-summary` 拿有界摘要 → 拼 prompt → 一次 OpenAI 兼容直调（local-first 默认 Ollama，provider 细节归 T7）→ 解析 JSON 方案数组 → 落 `intent_cards` → 发事件给前端。无会话、无工具循环。
3. **节拍与判据分离**（响应用户「不断累积评估、不是到点就出卡」的定调）：心跳只有观察权没有出卡权。每次醒来拉增量信号（`ui_events` 的 app_switch/window_focus 计数、`frames` 的 simhash/content_hash 变化），过自写规则门槛才发起生成调用；生成调用本身仍允许模型回答「材料不足」。阈值数值是实现期调参项，不是本图决策。
4. **上下文累积 = 查询窗口增长**：数据已由采集引擎持续落库，「攒上下文」实现为查询窗口从上一张卡时刻滚到现在，不新建任何存储组件；跨窗持久摘要将来若需要再议（见地图雾区 Daily Summary 持久化存档）。
5. **常驻语义**：只要采集引擎在跑就生成，不要求主窗口打开（托盘挂窗口关算数）。调度器住 Rust 侧，与引擎同生命周期；引擎完全停止则无材料可生成，属物理边界。具体宿主进程（Tauri 托盘进程 vs 独立守护）实现期定。
6. **新手卡旁路**：新增一个 Tauri command 手动触发生成→落库→推送，跳过心跳与判据——即 T4 定的开发期测通载具。
7. **升级路径**：卡片质量不够时，把「拼简报→单次调用」一段换成 Pi 子进程会话（`daily-summary-pi.ts` 的渐进披露模式为先例）；表结构、触发层、展示层均不动。重写已在 T4 砍掉，不存在 agent 重入需求。

### 对 T7 的输入

直调形态走 OpenAI 兼容接口，Ollama 基线能否胜任、BYOK 引导、失败记账都在 T7 裁决。
