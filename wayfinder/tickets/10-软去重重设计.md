# T10 · 去重重设计：机械配额换软去重

Labels: wayfinder:ticket
Status: Resolved（2026-08-23）
Blocked by: 无

## Question

T4 决议 7 与计划 D2 定的 `dedup_key = {card_type}:{dominant_app}` 加 `unique(dedup_key, local_date)`，在 2026-08-23 的真实使用里暴露出结构性问题：重度单应用用户的 dominant_app 全天锁死，read_only 与 side_effect 名额上午耗尽后整天静默吞卡；三次心跳跑完完整 Pi 会话后全部命中唯一索引被丢弃，模型白跑、用户无感知。更根本的是这条规则防不住跨日重复打扰（零点重置，对 rejected 无记忆），又误伤同日同 app 的不同意图——它是伪装成去重的每日配额，而 card_type 由模型自选、dominant_app 由使用习惯决定，两个键都不受产品控制。

## Resolution

**作废 D2。判重交给生成模型自己做，数据库不再设唯一约束。**

1. **软去重**：心跳在材料里预载近 48 小时卡片清单（`intent_list_recent`，常量 `RECENT_CARDS_WINDOW_SECS` / `RECENT_CARDS_LIMIT` 在 gate.rs）；system prompt 写明判重规则——与清单中某卡意图相同或高度相近（尤其状态为 rejected）时提交 `insufficient_material`。需要查更早历史时模型可调 `sp_intent_cards_recent` 工具。
2. **读侧单一事实源走本地 API**：引擎新增只读路由 `GET /intent-cards/recent`（since_hours 默认 48、limit 默认 20 上限 100）。App 内预载与工具共用同一个查询函数；其他本地 agent 想要同一视图也走这条路由。刻意不建写路由：模型侧没有任何 HTTP 路径能创建或改写卡片，T8 决议 4 不变。
3. **schema 变更**：迁移 `20260823120000` 删除唯一索引（DROP INDEX，不重建表）。`dedup_key` 列保留继续写，降级为记录字段。新手卡幂等从唯一索引改为 `intent_spawn_onboarding_card` 内显式当日预检（`intent_find_id_by_dedup_key`）。`InsertOutcome::DedupHit` 移除，insert 直接返回新行 id。
4. **扩展单文件可独立分发**：`assets/extensions/intent-card-recent.ts` 只依赖 fetch 和 env（`SCREENPIPE_PORT` / `SCREENPIPE_LOCAL_API_KEY`），随会话受管安装的同时可整文件拷进外部 Pi agent 的 extensions 目录直接用。交卡契约仍在 `intent-card.ts`（submit_intent_card，pi 协议层 schema 校验），仅 App 内会话安装；外部分发版不含写侧。

### D6–D9 补录

这四条裁决在实现期做出但从未落盘（此前只活在代码注释里），按现实现反推补记：

- **D6 · 会话形态**：意图生成是专属 Pi 会话（session id `intent-card`、项目目录 `~/.screenpipe/pi-intent`、每拍起停），系统提示与工具白名单挂在会话配置上，supply 层不带。
- **D7 · 技能隔离**：会话目录内的用户技能镜像（带 `.screenpipe-managed` marker）每次运行前清除，只留基线技能；安全性依赖该目录为 intent 会话独占。
- **D8 · 三级供给链不降级**：slot → mirror → builtin 只解析配置，运行期失败不跨级回退，下一拍同级重试。
- **D9 · 双窗口锚点**：材料窗口锚最后一次成功插入（失败时上下文持续累积，R2 封顶 7 天）；信号窗口锚最后一次尝试（任何结局都推进锚点，防止插不进时闸门常开形成重试风暴）。DedupHit 曾按 D9 静默处理，本票落地后该路径已不存在。

### 顺带修复的 supply 层缺陷

- `intent_get_supply` 的懒初始化会在 slot 键缺失时把内置 Ollama 写进 slot；slot 在链中优先于 mirror，设置页开一次就永久击穿「跟随 Chat」。已删除写回，slot 为空就返回 None，builtin 兜底由 `resolve_chain(None, None)` 承担。
- mirror 上报点从 chat 会话生命周期 hook 收敛进 `writeActiveAiPresetId`（新增 `reportActiveAiPresetId` 汇点），brain-overview 等不挂该 hook 的切换面不再漏报；hook 只保留启动时机的上报。

### 成本边界

心跳节拍（900s）是成本硬顶，判重失效的最坏结果是一天几十次会话里多几张重复卡，通知面板闸门兜底。不设机械保险丝；若实测命中率不可接受，最粗兜底是同 app 单日 COUNT 检查，一条查询的事，届时另议。

## Implementation notes

落点：screenpipe-db（迁移 + `intent_list_recent` / `intent_find_id_by_dedup_key`）、screenpipe-engine（routes/intent_cards.rs）、src-tauri intent_agent（runner 预载、instruct 判重规则、gate 常量、session 白名单加 `sp_intent_cards_recent`）、前端（active-ai-preset.ts 汇点）。验证：screenpipe-db 9/9、src-tauri 39/39、tsc 与相关 vitest 全绿。扩展已拷贝至本机 Pi agent 全局扩展目录（`~/.pi/agent/extensions/`）。
