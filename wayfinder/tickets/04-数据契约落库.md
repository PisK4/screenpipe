# T4 · 数据契约落库方案

Labels: wayfinder:grilling (HITL)
Blocked by: [T2 · 数据映射调研](02-数据映射调研.md)
Claimed by: pis（本会话，2026-08-22）

## Question

按 fork 的迁移风格给意图卡片建最小 schema，然后逐字段过一遍 T2 的映射表，决定取舍：哪些合同字段值得带上（候选：`status` 五值、`dedup_key`+`local_date` 去重、`proactive_view`、过期时间），哪些明确不进第一版（候选：`input_scope` 记账三件套、`source_refs` 校验闸门、记忆确认流、`anchor_id` 残留列）。生成输入就用 fork 现成数据（frames / elements / ui_events / activity-summary 路由），不为了合同的记忆预算去建记忆基底；《09》§3.1 当参照看，不当蓝本抄。

## Resolution

Status: Resolved
Claimed by: pis（2026-08-22，与用户逐项裁决）

### 表结构（v1 最小版，fork 迁移风格）

```sql
CREATE TABLE intent_cards (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  origin TEXT NOT NULL CHECK (origin IN ('proactive','system_onboarding')),
  card_type TEXT NOT NULL CHECK (card_type IN ('light','side_effect','read_only')),
  status TEXT NOT NULL DEFAULT 'proposed'
    CHECK (status IN ('proposed','shown','accepted','rejected','expired')),
  proactive_view TEXT,
  dedup_key TEXT NOT NULL,
  local_date TEXT NOT NULL,
  plans_json TEXT NOT NULL,
  model_id TEXT,
  shown_at INTEGER,
  expires_at INTEGER,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);
CREATE UNIQUE INDEX idx_intent_cards_dedup ON intent_cards(dedup_key, local_date);
```

### 逐项裁决

1. **重写流程第一版不做**：`rewrite_prev_card_id` 与 `adjust_opened_at` 都不建列；用户对方案不满意时第一版只有「不要」。将来随执行链路 effort 重估。
2. **新手接入卡保留**：`origin` 建列。它兼任开发期测通全链路的载具——手动触发一张卡走完生成→落库→展示→终态，不依赖真实触发条件。此用法是 T5（新手卡摆位）与 T3（触发层需可旁路）的硬输入。
3. **`model_id` 保留**：local-first 默认本机小模型，卡片质量排查需要。
4. **状态五值照搬合同**：`proposed/shown/accepted/rejected/expired`。`proposed` 与 `shown` 分开保护过期时钟从「用户有机会看到」起算（主动式生成可能没人看着）；三个终态分开为将来反馈账留信号；SQLite CHECK 改值要重建表，多留一个值比日后迁移便宜。
5. **日界口径照搬全 App 现有约定（本地自然日）**：`local_date` 存 `format(date, "yyyy-MM-dd")` 本地字符串，与 Daily Summary 缓存键（`components/rewind/timeline/daily-summary.test.tsx`）和搜索分天（`lib/search/result-facets.ts` 的本地日期分桶注释）一致。零点后生成的卡算新一天、去重桶重置；深夜场景归 T3 的触发时机管，不改日界定义。
6. **过期用单列 `expires_at`**：进入 `shown` 时写入 `shown_at + 48h`；终态即止。不引入合同的 `expiry_base_at`「有人动才重置」机制——重写不做之后没有可重置的交互。（2026-08-22 补记：统一 48h 对《04》§3 轻提示免过期规则是有意偏离，裁决与理由见 T8 决议第 2 条。）
7. **`dedup_key` 第一版取简单拼接口径**（卡片类型 + 核心对象标识），不追《04》§6 里未核实的 `step_hash` 算法。

### 明确不带（相对《09》§3.1）

`output_id` 连带整个 `model_outputs` 表、`input_scope` 记账三件套、`source_refs` 校验闸门、记忆确认流、`risk_level`、`anchor_id`、`thread_id`（执行链路进来再加）、`intent_card_feedback` 表。

### 连带效应

生成输入全部来自 fork 现成数据（frames / elements / ui_events / activity-summary 路由，见 T2 映射表），不建任何记忆基底。地图雾区的「记忆最小基底」条目就此关闭。
