## Question

卡片工作台建在哪——新主界面区域、Home/timeline 改造（`app/(main)/page.tsx`），还是复用 overlay / notification-panel 窗口？「轻提示」形态用什么承载？合同的三 Filter（待决定/执行中/已结束）与《03-产品功能地图》呈现投影如何对齐（注意执行中 Filter 依赖后置的执行链路，第一版怎么摆）？`system_onboarding` 新手接入卡是否随第一版走？

## Resolution

Status: Resolved
Claimed by: pis（2026-08-22，与用户逐项裁决）

### fork 侧证据

窗口全部由 Rust 动态创建，`tauri.conf.json` 的 `windows` 为空；清单在 `src-tauri/src/window/show.rs` 的 `RewindWindowId`：main（快捷键呼出的全屏 timeline overlay）、home、search、chat、onboarding、permission-recovery。另有 `notification-panel`（340×380 右上角通知面板，macOS 侧有原生 SwiftUI 面板回退，带静音/勿扰/冷却闸门，见 `commands.rs` 的 `deliver_notification_panel`）与 `notification-inbox`（历史收件箱）。主窗口是 section 切换结构：`app/(main)/home/page.tsx` 左栏 `SidebarNavList` 七个入口（用户可拖拽排序与隐藏），中栏按 `?section=` 渲染视图；新增 section 是现成模式。Rust→前端推送走 Tauri emit/listen，无基础设施缺口。

### 决议

1. **工作台挂点：主窗口新增「工作台」section**。照 `activity`/`pipes` 的现成模式在左栏加一行，中栏渲染卡片列表；不改 chat 首屏，不动 overlay 与 notification-panel 的现有职责。对《03》「工作台是首页、左栏七入口」的偏差如实记录：fork 的左栏入口本就由用户自定义排序，工作台作为新增行进入该体系，默认排位实现期定；《03》的首页地位不搬。
2. **轻提示承载：裁决面在工作台列表，提醒面复用 notification-panel**。到卡时走 `show_notification_panel` 弹一条提醒，静音/勿扰/冷却闸门照单全收，不另设开关；点提醒打开主窗口工作台。卡片本体与其他类型同列表，仅按钮组不同（《03》§3 按钮表照抄受下一节收窄约束）。
3. **Filter 第一版两个：待决定、已结束**。「执行中」随执行链路 effort 一并补位。已结束第一版只收 accepted（轻提示「知道了」与提案接受）；rejected/expired 按《04》语义离开工作台，回看页不进本图，落库记录即可。
4. **新手接入卡随第一版走**：`origin='system_onboarding'` 卡进待决定列表，由 T3 定的旁路 command 触发生成，兼任开发期测通的用户可见形态。不过期、不计入任何徽标计数（《04》§3 规则照抄）。

### 连带收窄（随地图 out-of-scope 自然产生）

- 「在对话里继续」「执行选中方案」的完整语义依赖应答通道交接，本图不做。第一版按钮组收窄：轻提示为「知道了 / 不要」，提案为「接受 / 不要」；接受只写终态，不开 Thread。《03》§3 按钮表的剩余交互随执行链路 effort 回补。
- 状态呈现用库状态五值直译；工作台 Filter 是呈现层不是新状态（《04》§1 已定）。
- 卡片文案与 i18n 键清单不在本票定稿，归 T6 原型之后的 i18n 定稿（地图雾区已有此条）。
