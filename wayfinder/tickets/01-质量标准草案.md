## Question

把用户的不满「卡片太泛、没有具体依据」转成**可判定**的质量标准草案，作为后续所有文本票的裁决依据：

1. 出卡门槛：什么材料够格出一张卡（证据的最小具体度——能指到哪个 app、哪段原文、哪个项目）？什么情况必须 `insufficient_material`？
2. 依据显影：卡片三字段（title / proactive_view / plans）各自必须携带什么，才能让只看前端的用户看出「这是从我的行为里读出来的」；
3. 定义钉死：「意图卡片 = 用户下一步最可能手动执行的任务」这句话里，「任务」的粒度与「下一步」的时限；
4. 标准草案先经用户确认，再交给流程文本票与文案风格票引用；效果由验证票用轨迹事后检验。

## Resolution

Status: Resolved
Claimed by: pis（走图会话，2026-08-25）

### 定义钉死

意图卡片是**步进级**任务预告：项目内的一步 ＋ 可命名的具体对象 ＋ 可启动的动作。动作级太窄、主题级即「太泛」的病根，均排除。「下一步」＝ 任务在 **48h 内可执行**，且支撑它的行为证据必须来自**当前生成窗口**——防止拿旧线索出陈卡。

### 出卡门槛（下限）：四要件

全部满足才允许考虑交卡，缺一即提交 `{"insufficient_material": true}`：

1. **具体对象**：能指名到 app / 文档 / 人 / 项目名，不接受「用户在忙工作」级别的泛指；
2. **强度信号**：时长或切换次数达到阈值（数值实现期标定）；
3. **自然下一步**：能从行为里说出用户卡在哪、接下来顺手该做什么；
4. **问题陈述**：能填完「用户当前面临的具体摩擦是 __，这张卡帮他解决了 __」——只有「用户在做 X」而没有「X 里的坎」不算。

### 行为闸门：自检问句

提交前自问：用户此刻看到这张卡，第一反应是「对，我正要弄这个」还是「关掉别烦我」？后者按 `insufficient_material` 处理。

### 默认方向：宁缺毋滥

`insufficient_material` 是**默认出口**，出卡是例外；四要件只是「允许出卡」的下限，全满足并过自检才交。材料未熟走 `save_intent_draft` 攒观察——草稿是把观察攒到能打动人为止的期票，不是出卡失败的替补。

### 依据显影：三字段必携的信息要素

表达风格归文案风格票定稿，本票只锁信息要素：

- **title**：必含具体对象的名字（要件①的那个）；
- **proactive_view**：必引至少一条当前窗口内的行为事实（哪个 app、多久、什么内容线索），并承载要件④的问题陈述；禁止出现帧数、原始 JSON 等用户无法解读的机器材料；
- **plans**：每条必须是可独立启动的动作句；禁止「了解一下…」「持续关注…」类不可判定措辞。

### 下游引用

- 完整生成流程文本票：system prompt 与 cue-tools skill 必须写入四要件、自检问句、默认出口倾斜；
- 文案风格票：原型对照的正反例以本标准为裁决线；
- save_intent_draft 机制票：收敛线语义依本票「期票」定义，renew 阈值数值仍由该票裁。
