# 一轮调优的检查单

## 开工前

- [ ] 失败已定类（对照 SKILL.md §1 表格），计数 ≥3 轮同类才立项修
- [ ] 确认修复层：过一遍四条裁决（wrapper / 材料 / 语言分界 / 契约同步）
- [ ] 查台账与 FEATURE 文档 §13 联动表，列出本次改动的全部同步点
- [ ] 改契约时两侧清单：extension schema ↔ parse.rs ↔ DB 列 ↔ 文档
- [ ] 记录改动前的基线数字（发生率 / 分类计数 / token 区间）

## 观察期

- [ ] 重装后确认旧进程已完全退出（跑着的可能是旧二进制）
- [ ] 区分哪些改动需要重装生效、哪些下一拍生效
- [ ] 攒满 ≥3 拍再评估；单轮异常先复现再下结论
- [ ] ATA 与原始 jsonl 两边对照，pending 死亡在磁盘上可能无痕

## 收尾

- [ ] 三样必报：目标行为率、失败分类计数对比、token 区间
- [ ] 未修复的失败类型写明去向（换槽 / 另立票 / 继续观察）
- [ ] 台账追加一行：日期、改动、基线 → 结果
- [ ] 文档同步：FEATURE_TOOLS_REFERENCE 对应小节 + doc-verified 刷新 + 父仓库 gitlink
